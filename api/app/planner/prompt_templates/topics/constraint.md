# Constraint Topic

## PMI Definition
Constraints are limiting factors that affect the execution of a project or process. They represent boundaries within which the project must be delivered and include factors like budget, schedule, resources, scope, quality, and regulatory requirements.

## What to Understand
- Fixed constraints (non-negotiable)
- Flexible constraints (some room to adjust)
- Triple constraint trade-offs (scope, time, cost)
- Regulatory or compliance constraints
- Technical constraints

## What to Infer
From project context, infer:
- Budget constraints from organizational context
- Timeline constraints from business drivers
- Resource constraints from team availability
- Technical constraints from existing systems

## What to Probe (Only if Missing)
- "What's absolutely fixed - the deadline, the budget, or the scope?"
- "Are there any compliance or regulatory requirements?"
- "What technical limitations should we work within?"

## Intelligent Behaviors
- Clarify the priority when constraints conflict
- Flag unrealistic constraint combinations
- Connect constraints to risk identification
- Suggest constraint prioritization framework
- Recommend documenting constraint trade-off decisions

## Common Pitfalls to Flag
- All constraints marked as non-negotiable
- Constraints that make project infeasible
- Missing regulatory/compliance constraints
- Constraints not communicated to team
- No documented trade-off decisions

## Constraint Categories
| Category | Examples |
|----------|----------|
| Time | Hard deadlines, regulatory dates, market windows |
| Cost | Fixed budget, funding cycles, approval limits |
| Scope | Must-have features, excluded functionality |
| Quality | Performance requirements, SLAs, standards |
| Resource | Team size, skill availability, tools |
| Regulatory | Compliance requirements, legal mandates |
| Technical | Platform limitations, integration requirements |
