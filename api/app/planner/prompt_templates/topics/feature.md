# Feature Topic

## PMI Definition
Features are distinguishing characteristics of a product or service. In software development, features represent user-facing capabilities that deliver value. They are typically decomposed into user stories and tasks for implementation.

## What to Understand
- Core features (must-have for MVP)
- Secondary features (nice-to-have)
- Feature prioritization
- User value of each feature
- Technical complexity

## What to Infer
From requirements and scope, infer:
- Feature groupings from requirements
- Priority from business value
- Dependencies between features
- MVP vs future release candidates

## What to Probe (Only if Missing)
- "What are the must-have features for first release?"
- "How would you prioritize these if time runs short?"
- "Which features provide the most value to users?"

## Intelligent Behaviors
- Group related features logically
- Flag feature dependencies
- Suggest prioritization framework
- Connect features to requirements
- Identify MVP candidates

## Common Pitfalls to Flag
- Feature bloat - too many for timeline
- All features marked as priority 1
- Features not tied to requirements
- Missing user value for features
- Technical features without business justification

## Feature Prioritization Methods
| Method | Description |
|--------|-------------|
| MoSCoW | Must, Should, Could, Won't |
| RICE | Reach, Impact, Confidence, Effort |
| Kano | Basic, Performance, Delighter |
| Value vs Effort | 2x2 matrix prioritization |

## Software Development Context
- How features relate to user stories
- Epic → Feature → Story → Task hierarchy
- Sprint planning implications
- Tech debt as "invisible features"
