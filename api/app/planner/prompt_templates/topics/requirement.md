# Requirement Topic

## PMI Definition
Requirements are conditions or capabilities that must be met or possessed by the project deliverables to satisfy a contract, standard, specification, or other formally imposed document. They describe what the solution must do (functional) and how well it must perform (non-functional).

## What to Understand
- Functional requirements (what it must do)
- Non-functional requirements (performance, security, usability)
- Business requirements (why it's needed)
- Technical requirements (how it will work)
- Acceptance criteria

## What to Infer
From goals and scope, infer:
- Implied functional requirements
- Performance expectations
- Security and compliance requirements
- Integration requirements

## What to Probe (Only if Missing)
- "How will users interact with this solution?"
- "Are there performance expectations? Response times, capacity?"
- "What security or compliance requirements apply?"

## Intelligent Behaviors
- Distinguish between requirements and wishes
- Flag conflicting requirements
- Suggest acceptance criteria format
- Connect requirements to goals
- Prioritize using MoSCoW or similar

## Common Pitfalls to Flag
- Requirements without acceptance criteria
- Solution masquerading as requirement ("use React")
- Missing non-functional requirements
- Gold plating - more than needed
- Requirements not tied to goals

## Requirement Types
| Type | Examples |
|------|----------|
| Business | "Reduce manual processing by 50%" |
| Functional | "System shall allow users to login" |
| Non-Functional | Performance, security, usability |
| Technical | Integration, platform, standards |
| Transition | Training, data migration, rollout |
