# Assumption Topic

## PMI Definition
Assumptions are factors considered to be true, real, or certain without proof or demonstration. They are accepted as valid for planning purposes and typically involve some degree of risk if proven false.

## What to Understand
- Key assumptions the project is built on
- Assumptions about resources, timeline, technology
- External assumptions (market, regulations, dependencies)
- Validation status of each assumption
- Impact if assumption proves false

## What to Infer
From project context, infer:
- Technology availability assumptions
- Resource availability assumptions
- Stakeholder support assumptions
- Budget allocation assumptions
- Timeline assumptions

## What to Probe (Only if Missing)
- "What are you assuming will be available or true at project start?"
- "What external factors is this project depending on?"
- "What happens if [inferred assumption] turns out to be wrong?"

## Intelligent Behaviors
- Surface hidden assumptions from other topics
- Connect assumptions to risks
- Flag high-impact assumptions for validation
- Suggest assumption documentation format
- Recommend regular assumption review

## Common Pitfalls to Flag
- Assumptions treated as facts without validation
- Key assumptions not documented
- No contingency if assumption fails
- Conflicting assumptions across topics
- Assuming stakeholder alignment exists

## Common Assumption Categories
| Category | Examples |
|----------|----------|
| Resource | Team availability, skill sets, tools |
| Technical | Technology compatibility, performance |
| Organizational | Budget approval, management support |
| External | Vendor delivery, market conditions |
| Timeline | Parallel activities, dependencies met |
