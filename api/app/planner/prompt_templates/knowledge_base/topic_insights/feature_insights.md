# Feature Topic Insights

## Real-World Experience

### Do's
- Size features against the timeline - don't commit to more than you can deliver
- Use relative estimation (story points) for comparison - absolute estimates are often fiction
- Group related features for planning - dependencies within groups are easier to manage
- Demo features early and often - feedback beats speculation
- Track feature value delivered, not just features shipped - quantity isn't quality

### Don'ts
- Don't treat all features as equal priority - force ranking reveals what truly matters
- Don't skip MVP conversations - what's the smallest thing that delivers value?
- Don't estimate features you don't understand - ask questions first
- Don't let the loudest voice drive feature priority - data beats opinions

### Warnings
- Feature lists grow faster than they shrink - be vigilant about adding
- "Easy features" often aren't - integration, edge cases, and polish consume time
- Features without user value are waste - always ask "who benefits?"
- Feature-complete isn't project-complete - testing, deployment, and stabilization remain

### Recovery Tips
- If behind on features, cut the backlog ruthlessly - ship fewer things that work
- Split large features into incremental deliverables - partial value is better than all-or-nothing
