# Rollout Phase Topic Insights

## Real-World Experience

### Do's
- Start with a pilot - even small pilots catch problems that testing misses
- Choose pilot groups who are forgiving but honest - friendly critics, not fans
- Define clear criteria for expanding to the next phase - what proves readiness?
- Plan hypercare support for go-live - issues will surface, response time matters
- Communicate rollout schedule early and often - surprises breed resistance

### Don'ts
- Don't skip pilot even under pressure - the time you save creates risk you pay later
- Don't expand from pilot without addressing pilot issues - same issues will recur at scale
- Don't underestimate training dependencies - untrained users create support burden
- Don't ignore change fatigue - users have limits on how much change they can absorb

### Warnings
- Go-live dates that can't slip create pressure for shortcuts - be honest about readiness
- Rollback plans that aren't tested won't work when you need them
- User adoption doesn't happen automatically - plan for champions, training, support
- Parallel running has hidden overhead - running two systems is work

### Recovery Tips
- If rollout fails, stabilize before expanding - stop the bleeding first
- When adoption is low, diagnose before demanding - is it training, capability, or willingness?
